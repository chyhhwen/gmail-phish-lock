# 上架到公司內部商店（只限公司網域）

照順序做，每一步完成再往下。後台畫面的文字可能跟這裡略有不同，以實際畫面為準。

## 這個資料夾裡的東西

| 檔案 | 用在哪裡 |
|---|---|
| `store-icon-128.png` | 商店資訊分頁 → 商店圖示 |
| `screenshot-1-1280x800.png`、`screenshot-2-1280x800.png` | 商店資訊分頁 → 螢幕截圖 |
| `promo-440x280.png` | 商店資訊分頁 → 小型宣傳圖塊 |
| `privacy-policy.html` | 放到公司網站，網址填在隱私權分頁 |

要上傳的套件是 **`gmail-phish-lock-extension-v0.2.1.zip`**，它的 `manifest.json` 在 zip 最外層。可以從 GitHub Releases 下載，也可以在原始碼根目錄跑 `node scripts/build-release.js` 打包，檔案會產生在 `dist/`。

截圖裡的郵件畫面是模擬的，紅色鎖定和右側卡片上的原因，都是插件實際判斷的結果。想換成真的 Gmail 截圖也可以，但畫面上不要出現任何真實信件。

## 一、事前準備（只做一次）

**1. 管理員開啟網域限定發佈**

管理控制台 → 裝置 → Chrome → 應用程式和擴充功能 → 使用者應用程式設定 → 「Chrome 線上應用程式商店權限」，勾選允許使用者發佈限定網域的私人應用程式。英文介面的文字是：

> Allow users to publish private apps that are restricted to your domain on Chrome Web Store

**2. 建立開發人員帳號**

- 用**公司網域**的帳號註冊。建議開一個專用帳號，因為帳號建立後就不能改信箱。
- 帳號要先開兩步驟驗證，否則不能發佈。
- 一次性註冊費 5 美元。
- 驗證聯絡信箱。
- 發佈者名稱建議填「【公司名稱】IT」。
- 商家身分選「非商家」。

**3. 放上隱私權政策**

把 `privacy-policy.html` 裡的【公司名稱】、【聯絡信箱】換成實際內容，放到公司網站上。放好後用無痕視窗打開一次，確認**不用登入**就看得到。

## 二、上傳套件

開發人員後台 → 新增項目 → 上傳 `gmail-phish-lock-extension-v0.2.1.zip`。

## 三、商店資訊分頁

**說明**（整段貼上）：

```
釣魚連結鎖 for Gmail 會在你打開信件時，檢查信裡的每一個連結，把可疑的連結鎖住並標成紅色，點了也不會開啟。

會被鎖住的連結：
・網址冒用 PayPal、Microsoft、Google 等品牌，或用 0、1 這類字元換字仿冒
・連結文字寫的是 A 網址，實際卻連到 B
・直接連 IP 位址、用 @ 偽裝網址、短網址
・架在免費架站平台或雲端儲存空間上的網頁
・常被拿來做釣魚的網域結尾，或網域名稱帶有 login、account、verify 這類字

隱私：所有判斷都在你的瀏覽器裡完成，不連網、不收集、不傳送任何資料。

公司 IT 可以透過 Chrome 企業政策，設定信任的網域、要保護的公司品牌，以及是否允許同仁自行開啟被鎖住的連結。

如果 Gmail 改版導致插件認不得信件內容，畫面左下角會跳出警告，不會默默失效。

本插件為公司內部使用的安全工具，不是 Google 官方產品。Gmail 是 Google LLC 的商標。
```

**類別**：隱私權與安全性（Privacy & Security）

**語言**：中文（繁體）

**圖片**：依上方表格上傳商店圖示、兩張截圖、小型宣傳圖塊。

## 四、隱私權分頁

**單一用途**：

```
在 Gmail 網頁上找出信件裡的可疑連結並鎖住，防止使用者誤觸釣魚網站。
```

**權限理由**：

`storage`：

```
只用來讀取公司 IT 透過 Chrome 企業政策設定的選項（chrome.storage.managed），例如信任的網域、要保護的公司品牌、是否允許自行開啟被鎖住的連結。本插件不會寫入或儲存任何使用者資料。
```

主機權限（`https://mail.google.com/*`）：

```
本插件只在 Gmail 網頁上執行：讀取信件內文裡連結的網址與文字，在瀏覽器本機判斷是否為釣魚連結，可疑的就移除連結並標成紅色。不存取其他網站，也不傳送任何資料。
```

**遠端程式碼**：選「否，我沒有使用遠端程式碼」。

**資料使用**：勾「個人通訊」和「網站內容」這兩類。

插件會在本機讀取信件裡連結的網址與文字，這屬於電子郵件內容。官方 FAQ 明講，只在本機處理也要揭露，所以兩類都要勾。資料不會離開瀏覽器，這點隱私權政策裡有寫清楚。

下方的三個聲明全部勾選：不出售或轉移資料給第三方、不用於單一用途以外的目的、不用於信用評估或借貸。

**隱私權政策網址**：填第一段第 3 步放好的網址。

## 五、發佈分頁

1. 可見度選「私人」，範圍選「機構內所有使用者」。英文介面是 `All users in <機構名稱>`。
2. 按「提交審查」，並勾選「審查通過後自動發佈」。

審查通常幾天，最長可能幾週。

---

## 六、審查通過之後

1. 後台狀態會顯示 `Published - Private (Domain)`。
2. 記下插件 ID，就是後台項目網址或商店頁網址裡那串 32 個英文字母。**這個 ID 跟開發人員模式下的不一樣。**
3. 先把你電腦上用開發人員模式載入的那份移除，避免兩份同時執行。
4. 管理控制台 → 裝置 → Chrome → 應用程式和擴充功能 → 使用者和瀏覽器 → 用 ID 加入插件 → 安裝政策選「強制安裝」。
5. 在同一頁的「Policy for extensions」貼政策 JSON。每個值都要包一層 `{"Value": …}`，範例在主 README 的「管理員政策」一節。
6. 照主 README 的「驗證」一節，先在一台電腦上確認：
   - `pgVersion` 印出 `'0.2.1'`
   - `pgPolicy` 印出 `'managed'`
   - 測試信裡的 `.example` 連結有被鎖住
   
   全部都對，再套用到全公司。

---

## 七、之後要更新時

1. 改版本號。下面兩處要一致，而且一定要比上一版大，例如 `0.2.1` → `0.2.2`：
   - `extension/manifest.json` 的 `version`
   - `extension/detect.js` 的 `VERSION`
2. 在原始碼根目錄跑 `node scripts/build-release.js` 打包。版本號不一致、檔案缺漏或編碼不對，它會直接失敗並說明原因。
3. 後台上傳 `dist/` 裡的新 zip 並提交審查。**每次更新都要重新審查**，審查通過後會自動更新到每位同仁的瀏覽器。
